### ۱-ب. اگر قبلاً schema.sql را اجرا کرده‌ای
فقط `supabase/migration-portfolio.sql` را اجرا کن تا نمونه‌کارها «توضیح» و «لینک» داشته باشند. تا وقتی اجرا نشود، همه‌چیز مثل قبل کار می‌کند (فقط بدون توضیح/لینک).

### ۱-ب۲. نظرات نمونه‌کارها (جدید)
اگر قبلاً `schema.sql` را اجرا کرده‌ای، فقط `supabase/migration-comments.sql` را هم در SQL Editor اجرا کن (نصب تازه نیازی ندارد؛ در schema.sql هست). هر بازدیدکننده می‌تواند زیر هر پروژه نام و نظر بگذارد؛ نظرها به‌صورت **ورق‌زن** نمایش داده می‌شوند (یک نظر در هر صفحه؛ دکمهٔ قبلی/بعدی، نقطه‌ها، سوایپ روی موبایل و کلیدهای ← → روی کیبورد)؛ نظرها در جدول `project_comments` ذخیره می‌شوند و مدیر از تب «💭 نظرات» پنل می‌تواند حذفشان کند. محدودیت: ۱۰ نظر در ساعت برای هر IP + تلهٔ ضدربات. تا اجرا نشود، بقیهٔ سایت مثل قبل کار می‌کند.

### ۱-ج. اعلان سفارش جدید در تلگرام (پیشنهاد جدی)
پنل فقط وقتی سفارش را نشان می‌دهد که بازش کنی (و بعد از ۵ دقیقه بی‌فعالیتی خودکار بسته می‌شود). برای اینکه هیچ سفارشی دیده نشود، مراحل داخل `supabase/notify-telegram.sql` را انجام بده. این فایل آزمایش‌نشده است؛ بعد از اجرا یک سفارش آزمایشی ثبت کن.

### ۲. تنظیمات Authentication
**Allow new users to sign up** خاموش باشد. برای امنیت بیشتر در همان بخش **MFA (TOTP)** را برای حساب مدیر فعال کن و رمز قوی بگذار.

### ۳. آدرس واقعی سایت
```bash
python3 tools/set-domain.py https://your-domain.com
```
این دستور `canonical`، `og:image`، `sitemap.xml` و `robots.txt` را درست می‌کند.

### ۴. انتشار
همهٔ فایل‌ها را آپلود کن. ورود مدیر: `https://your-domain.com/admin.html` (ایمیل + رمز).
پیشنهاد: نام فایل را عوض کن (مثلاً `admin-x7k2.html`). در `robots.txt` عمداً نوشته نشده تا آدرس پنل لو نرود؛ خود صفحه `noindex` است.

## نکته‌ها
- **داده‌ها فقط روی سرور** هستند؛ سفارش و گفتگو در `localStorage` ذخیره نمی‌شود. گفتگوی بازدیدکننده تا بستن تب (sessionStorage) می‌ماند.
- **همهٔ پیام‌های دستیار** (حتی بدون نام و شماره) همان لحظهٔ ارسال در جدول `chats` ذخیره می‌شود؛ اگر اینترنت قطع باشد، در صف می‌ماند و بعداً ارسال می‌شود. گفتگوهای بدون شماره در پنل با برچسب «بدون شماره» دیده می‌شوند.
- بخش «نمونه‌کارها» نمونه‌کارهای ثبت‌شده در پنل را نشان می‌دهد و زیرش چند «ایدهٔ نمونه» دارد.
- پنل، سفارش‌ها و **گفتگوها** را از سرور می‌خواند (نسخهٔ قبلی فقط گفتگوهای همان مرورگر را نشان می‌داد).
- عکس پروژه‌ها هنگام آپلود به WebP فشرده می‌شوند و برای کاور یک نسخهٔ کوچک (`-t.webp`) هم ساخته می‌شود. پروژه‌های قدیمی خودکار از عکس اصلی استفاده می‌کنند.
- `_headers` برای Netlify / Cloudflare Pages است (کش و هدرهای امنیتی)؛ در GitHub Pages نادیده گرفته می‌شود.
- **توقف پروژهٔ رایگان:** workflow گیت‌هاب هر ۳ روز یک ردیف می‌خواند. اگر ریپو ۶۰ روز بدون فعالیت بماند GitHub آن را متوقف می‌کند؛ یک مانیتور (UptimeRobot) هم به آدرس سایت وصل کن.
- محدودیت ثبت سفارش ۱۰ بار در ساعت برای هر IP و پیام‌های دستیار ۳۰۰ بار در ساعت است.

در **Authentication ← Sign In / Providers**، گزینهٔ **Allow new users to sign up** خاموش باشد و **Save changes** زده شده باشد. حتی اگر روشن بماند، فقط ایمیل مدیر دسترسی دارد، ولی خاموش بودنش بهتر است.

### ۳. انتشار سایت
فایل‌های این پوشه را جای فایل‌های قبلی سایتت آپلود کن. `js/config.js` از قبل با آدرس و کلید پروژه‌ات پر شده است.

### ۴. تست
1. سایت را باز کن و یک سفارش آزمایشی ثبت کن. در Supabase، **Table Editor ← orders** باید یک ردیف جدید ببینی.
2. از دکمهٔ پنل مدیریت با رمز مدیر (همانی که در Authentication ← Users گذاشتی) وارد شو. سفارش را باید ببینی.
3. در پنل، یک پروژه با چند عکس اضافه کن. در **Storage ← projects** پوشهٔ عکس‌ها ساخته می‌شود و در بخش «پروژه‌های ما» از گوشی/مرورگر دیگر هم دیده می‌شود.

## نکته‌ها

- **کلیدها:** کلید `publishable` را می‌شود در فرانت گذاشت. کلید `secret` یا `service_role` را هرگز در سایت یا ریپو نگذار.
- **رمز مدیر** را از Authentication ← Users عوض می‌کنی. نشست ورود حدود یک ساعت اعتبار دارد؛ بعد از آن پیام «نشست مدیر تمام شد» می‌آید و دوباره وارد می‌شوی.
- **توقف پروژهٔ رایگان:** طبق مستندات Supabase، پروژه‌های پلن رایگان که در یک هفته فعالیت کمی دارند متوقف می‌شوند. فایل `.github/workflows/keepalive.yml` هر ۳ روز یک درخواست کوچک می‌فرستد تا این اتفاق نیفتد (فقط اگر سایت روی GitHub باشد کار می‌کند). GitHub ممکن است زمان‌بندی‌ها را بعد از مدتی بی‌فعالیتی ریپو غیرفعال کند؛ اگر ایمیل هشدار Supabase گرفتی، کافی است یک بار وارد داشبورد پروژه شوی.
- **محدودیت تعداد درخواست:** ثبت سفارش ۱۰ بار در ساعت برای هر IP و پیام‌های دستیار ۳۰۰ بار در ساعت است. چون در موبایل ممکن است چند نفر IP مشترک داشته باشند، عددها عمداً سخاوتمندانه‌اند. اگر لازم شد در `schema.sql` عوضشان کن و دوباره اجرا کن.
- **قطعی اینترنت:** سفارش یا پیامی که به خاطر شبکه ارسال نشود در مرورگر کاربر می‌ماند و بعداً خودکار فرستاده می‌شود.
