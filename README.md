# Merteks — نسخهٔ Supabase

سفارش‌ها، گفتگوهای دستیار، ورود مدیر و پروژه‌ها (همراه عکس) همه روی Supabase ذخیره می‌شوند. به سرور یا Worker جدا نیازی نیست: سایت مستقیم با Supabase حرف می‌زند و قوانین امنیتی (RLS) داخل خود دیتابیس اعمال می‌شود.

## ساختار

```text
merteks/
├── index.html
├── css/style.css
├── js/config.js        ← آدرس پروژه، کلید publishable و ایمیل مدیر
├── js/app.js
├── assets/ms-logo.webp
├── supabase/schema.sql ← یک بار در SQL Editor اجرا می‌شود
└── .github/workflows/keepalive.yml
```

## راه‌اندازی

### ۱. اجرای SQL (یک بار)
1. در Supabase از منوی کنار وارد **SQL Editor** شو و **New query** بزن.
2. همهٔ محتوای `supabase/schema.sql` را کپی و جایگذاری کن.
3. بالای فایل، ایمیل مدیر (`admin_email`) باید دقیقاً همان ایمیلی باشد که در **Authentication ← Users** ساخته‌ای. اگر فرق دارد اول درستش کن.
4. دکمهٔ **Run** را بزن. باید پیام موفقیت ببینی (مثلاً *Success. No rows returned*).
5. اگر پیام خطا آمد، متن کامل خطا را برای من بفرست و خودت چیزی را عوض نکن.

### ۲. تنظیمات Authentication
در **Authentication ← Sign In / Providers**، گزینهٔ **Allow new users to sign up** خاموش باشد و **Save changes** زده شده باشد. حتی اگر روشن بماند، فقط ایمیل مدیر دسترسی دارد، ولی خاموش بودنش بهتر است.

### ۳. انتشار سایت
فایل‌های این پوشه را جای فایل‌های قبلی سایتت آپلود کن. `js/config.js` از قبل با آدرس و کلید پروژه‌ات پر شده است.

### ۴. تست
1. سایت را باز کن و یک سفارش آزمایشی ثبت کن. در Supabase، **Table Editor ← orders** باید یک ردیف جدید ببینی.
2. از دکمهٔ پنل مدیریت با رمز مدیر (همانی که در Authentication ← Users گذاشتی) وارد شو. سفارش را باید ببینی.
3. در پنل، یک پروژه با چند عکس اضافه کن. در **Storage ← projects** پوشهٔ عکس‌ها ساخته می‌شود و در بخش «پروژه‌های ما» از گوشی/مرورگر دیگر هم دیده می‌شود.

## نکته‌ها

- **کلیدها:** کلید `publishable` را می‌شود در فرانت گذاشت. کلید `secret` یا `service_role` را هرگز در سایت یا ریپو نگذار.
- **رمز مدیر** را از Authentication ← Users عوض می‌کنی. نشست ورود حدود یک ساعت اعتبار دارد؛ بعد از آن پیام «نشست مدیر تمام شد» می‌آید و دوباره وارد می‌شوی.
- **توقف پروژهٔ رایگان:** طبق مستندات Supabase، پروژه‌های پلن رایگان که در یک هفته فعالیت کمی دارند متوقف می‌شوند. فایل `.github/workflows/keepalive.yml` هر ۳ روز یک درخواست کوچک می‌فرستد تا این اتفاق نیفتد (فقط اگر سایت روی GitHub باشد کار می‌کند). GitHub ممکن است زمان‌بندی‌ها را بعد از مدتی بی‌فعالیتی ریپو غیرفعال کند؛ اگر ایمیل هشدار Supabase گرفتی، کافی است یک بار وارد داشبورد پروژه شوی.
- **محدودیت تعداد درخواست:** ثبت سفارش ۱۰ بار در ساعت برای هر IP و پیام‌های دستیار ۳۰۰ بار در ساعت است. چون در موبایل ممکن است چند نفر IP مشترک داشته باشند، عددها عمداً سخاوتمندانه‌اند. اگر لازم شد در `schema.sql` عوضشان کن و دوباره اجرا کن.
- **قطعی اینترنت:** سفارش یا پیامی که به خاطر شبکه ارسال نشود در مرورگر کاربر می‌ماند و بعداً خودکار فرستاده می‌شود.
